# 貢献

ご協力ありがとうございます。最も価値ある貢献は**訂正**です：誤った数値、言い過ぎた主張、欠けた注意書き、より良い文献。

## モジュール構成

各 `Module_NN_Name/` フォルダには次が含まれます：

| ファイル | 役割 | 規則 |
|---|---|---|
| `readme.md` | 📖 2420年の物語レッスン | タイトルと「ストーリーモード」バナーで始まり、続いて `レッスンタイトル`、`出典`、`概念` の箇条書きと番号付きセクション。想像的だが、読者に実在の医療を飛ばすよう促してはならない。 |
| `PHYSICS_PROOF.md` | 📜 作中の論証 | 「作中文書」バナーで始まる。セクション：8歳児向け、主題、公理、メカニズム、証明/含意。 |
| `SCIENCE.md` | 🔬 2025年の現実チェック | セクション：2420年の主張を一文で · レベル1 — 実在すること · レベル2 — 主張が破綻するところ · レベル3 — 何が真でなければならないか · 実験室を実行 · 自分で試す · 参考文献。 |
| `simulation.py` | 🧪 実験室 | スタンドアロン；NumPy と SciPy のみ；import 可能な純粋関数と `main()` レポート。実験室コードは英語モジュール側にあり、翻訳フォルダにはコピーしない。 |

テストは `tests/test_module_NN.py` にあり、共有の `sim` フィクスチャで実験室を読み込みます（ファイル先頭で `FOLDER = "Module_NN_Name"` を設定）。

## 実験室コードの規則

1. **循環的検証をしない。** 答えからパラメータを導いて、その答えを「確認」してはならない。構成上保証される結果なら、コメントでそう書き、証拠として提示しない。
2. **ハードコードされた評決を出さない。** 印刷される結論はすべて計算から得ること。
3. **破綻するところを示す。** 各実験室には、物語の主張を測定に対して試す計算を少なくとも1つ含める（真である部分だけではない）。
4. **テストは失敗できなければならない。** 解析的極限、スケーリング則、公表値を確認する。コードが自分自身からコピーした値ではない。
5. 各テストファイルは数秒以内に収める。

## 引用の規則

- 確認した情報源だけを引用する：著者、年、雑誌、巻、ページ。
- 一次論文と標準的な教科書を優先する。論争中の主張は両側を引用する。
- 「証拠なし」は、知識の現状がそうであるところでは、はっきりと、しかし優しく言う。

## プルリクエストを開く前に

```bash
python -m pip install -r requirements.txt
python -m pytest
```

英語のレッスンを変えた場合は、翻訳を更新できるようプルリクエストで言及してください。
